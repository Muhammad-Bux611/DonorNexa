1. Architectural Integration Pattern: Hybrid SSR + AJAX REST

DonorNexa employs an industry-standard Hybrid Integration Architecture:

  • Server-Side Rendering (SSR) via Thymeleaf: All core views, navigation shells, dashboards, tables, and form templates are rendered directly on the server before being delivered as complete HTML to the browser. This eliminates client-side hydration delays, provides zero-flicker rendering, and ensures strong SEO and security.
  • Client-Side Asynchronous REST (AJAX Fetch API): Dynamic micro-interactions — such as province-to-city cascading dropdowns, polling for in-app notification badges, and real-time chat updates — communicate asynchronously with Spring Boot @RestController endpoints returning JSON payloads.

2. Form Handling, Two-Way Binding & JSR-380 Validation

The bridge between user input in the browser and Java business objects in the backend is managed by Spring MVC's Two-Way Form Binding combined with JSR-380 Bean Validation.

2.1 End-to-End Data Flow: Donor Registration

Stage Backend Component Frontend Component
1. Initial Form Request AuthController.java exposes @GetMapping("/register/donor") and injects empty DonorRegistrationRequest into the model. Browser receives templates/auth/donor-register.html with blank input controls.
2. Template Binding Java attributes: fullName, email, phoneNumber, bloodGroup. Thymeleaf links form: th:object="${donorForm}" and inputs: th:field="*{fullName}".
3. Form Submission @PostMapping("/register/donor") captures @Valid @ModelAttribute("donorForm") and BindingResult. Browser posts form payload with hidden CSRF token: th:action="@{/register/donor}".
4. Validation Failure Handling If bindingResult.hasErrors(), controller returns template name without redirecting, preserving user input. Thymeleaf highlights error fields with is-invalid class and renders validation message via th:errors="*{email}".
5. Success Redirect (PRG) Service persists donor; controller adds flash message via RedirectAttributes and redirects to /login/donor. Browser navigates via clean GET request; renders flash message: th:if="${successMessage}".

2.2 Concrete Code Mapping: Backend DTO vs Frontend Template

Java Backend: DonorRegistrationRequest.java + Controller
// 1. DTO with JSR-380 Annotations
public class DonorRegistrationRequest {
    @NotBlank(message = "Full name is required")
    @Size(min = 2, max = 100)
    private String fullName;

    @NotBlank(message = "Email is required")
    @Email(message = "Please enter a valid email")
    private String email;

    @NotNull(message = "Blood group is required")
    private BloodGroup bloodGroup;
}

// 2. Controller POST Mapping
@PostMapping("/register/donor")
public String registerDonor(
        @Valid @ModelAttribute("donorForm") DonorRegistrationRequest form,
        BindingResult bindingResult,
        RedirectAttributes redirectAttributes,
        Model model) {

    if (bindingResult.hasErrors()) {
        model.addAttribute("provinces", locationService.getAllProvinces());
        return "auth/donor-register"; // Re-render template
    }

    authService.registerDonor(form);
    redirectAttributes.addFlashAttribute("successMessage", 
        "Account created! Please log in.");
    return "redirect:/login/donor"; // PRG Pattern
}

Viva Tip (Post/Redirect/Get Pattern): "Why do we return redirect:/login/donor instead of rendering the login template directly on success?"
Answer: "We use the PRG (Post/Redirect/Get) pattern. If the user hits browser refresh after submitting a form, a redirect prevents duplicate database inserts. Flash attributes survive the redirect via temporary session storage and are discarded immediately after rendering."

3. Global State Injection & Layout Composition

3.1 Global Dashboard Data Injection via @ControllerAdvice

Instead of repeating boilerplate code in every controller to inject the logged-in user profile, unread notification counts, and pending chat message badges, DonorNexa uses GlobalDashboardControllerAdvice.java:

GlobalDashboardControllerAdvice.java
@ControllerAdvice
@RequiredArgsConstructor
public class GlobalDashboardControllerAdvice {

    private final UserRepository userRepository;
    private final NotificationRepository notificationRepository;

    @ModelAttribute("currentUser")
    public User getCurrentUser(Authentication auth) {
        if (auth == null || !auth.isAuthenticated() 
            || "anonymousUser".equals(auth.getPrincipal())) {
            return null;
        }
        return userRepository.findByEmail(auth.getName()).orElse(null);
    }

    @ModelAttribute("unreadNotificationCount")
    public long getUnreadNotificationCount(Authentication auth) {
        if (auth == null || !auth.isAuthenticated()) return 0;
        User user = getCurrentUser(auth);
        return user != null ? notificationRepository
            .countByRecipientIdAndNotificationStatus(
                user.getId(), NotificationStatus.UNREAD) : 0;
    }
}

4. Client-Side AJAX & REST API Integration (Cascading Dropdowns)

When registering a voluntary donor or updating hospital facility records, selecting an administrative Province dynamically triggers an asynchronous HTTP GET request to fetch corresponding cities without reloading the page.

4.1 REST Controller Endpoint: LocationController.java

package com.donornexa.location.controller;

import com.donornexa.location.dto.CityDto;
import com.donornexa.location.service.LocationService;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequiredArgsConstructor
public class LocationController {

    private final LocationService locationService;

    /**
     * Endpoint: GET /api/locations/provinces/{provinceId}/cities
     * Serialized to JSON: [{"id": 1, "name": "Karachi"}, {"id": 2, "name": "Hyderabad"}, ...]
     */
    @GetMapping("/api/locations/provinces/{provinceId}/cities")
    public ResponseEntity<List<CityDto>> getCitiesByProvince(@PathVariable Long provinceId) {
        return locationService.getCitiesByProvinceId(provinceId)
                .map(ResponseEntity::ok)
                .orElseGet(() -> ResponseEntity.notFound().build());
    }
}

4.2 Client-Side JavaScript Fetch API: location-dropdown.js

/**
 * location-dropdown.js — Asynchronous Cascading Dropdown Handler
 */
document.addEventListener('DOMContentLoaded', function () {
    const provinceSelect = document.getElementById('provinceSelect');
    const citySelect = document.getElementById('citySelect');
    const citySpinner = document.getElementById('citySpinner');

    if (!provinceSelect || !citySelect) return;

    provinceSelect.addEventListener('change', function () {
        const provinceId = this.value;
        if (!provinceId) {
            citySelect.innerHTML = '<option value="">Select Province First</option>';
            citySelect.disabled = true;
            return;
        }

        // 1. Show loading spinner and disable control
        citySpinner.classList.remove('d-none');
        citySelect.disabled = true;
        citySelect.innerHTML = '<option value="">Loading cities...</option>';

        // 2. Execute asynchronous Fetch API call to Spring Boot REST endpoint
        fetch('/api/locations/provinces/' + encodeURIComponent(provinceId) + '/cities')
            .then(response => {
                if (!response.ok) throw new Error('HTTP ' + response.status);
                return response.json(); // Parse JSON payload
            })
            .then(cities => {
                citySpinner.classList.add('d-none');
                citySelect.innerHTML = '<option value="">Select City</option>';

                // 3. Dynamically populate select options
                cities.forEach(city => {
                    const opt = document.createElement('option');
                    opt.value = city.id;
                    opt.textContent = city.name;
                    citySelect.appendChild(opt);
                });

                citySelect.disabled = false; // Re-enable control
            })
            .catch(error => {
                citySpinner.classList.add('d-none');
                citySelect.innerHTML = '<option value="">Error loading cities</option>';
                console.error('Location fetch error:', error);
            });
    });
});

5. Security, CSRF Tokens & Session Architecture

5.1 Cross-Site Request Forgery (CSRF) Protection Flow

Spring Security 6 automatically enforces CSRF verification for all state-modifying requests (POST, PUT, DELETE). Without a valid CSRF token, the server returns HTTP 403 Forbidden.

Server generates secure CSRF Token in session │ │ Renders <input type="hidden" name="_csrf" value="abc-123-token"/> │ │<────────────────────────────────────────────────────────────────────────┤ │ │ │ 3. User submits form: POST /register/donor │ │ Includes _csrf token in request body │ ├────────────────────────────────────────────────────────────────────────>│ │ │ │ 4. 5.2 AJAX CSRF Header Configuration

For client-side JavaScript calls (e.g. marking a notification as read via POST), the CSRF token is exposed via HTML <meta> tags and passed in the HTTP request header: 

<!-- In Thymeleaf Header Template -->
<meta name="_csrf" th:content="${_csrf.token}"/>
<meta name="_csrf_header" th:content="${_csrf.headerName}"/>

<script>
// In client-side JavaScript
const token = document.querySelector('meta[name="_csrf"]').getAttribute('content');
const header = document.querySelector('meta[name="_csrf_header"]').getAttribute('content');

fetch('/api/notifications/mark-read/' + notificationId, {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        [header]: token // Injects X-CSRF-TOKEN header
    }
});
</script>

6. Viva Defense Cheat Sheet: Frontend-Backend Integration

Examiner Question Exact Defense Answer to Deliver
1. How does Thymeleaf communicate with Spring Boot? *"Thymeleaf is a server-side template engine tightly coupled with Spring MVC. When a controller method returns a view name string (e.g. return 'auth/login';), the ThymeleafViewResolver processes the corresponding HTML template, replacing th:* attributes with actual data evaluated from the org.springframework.ui.Model."*
2. How do you prevent double form submissions? *"We implement the PRG (Post/Redirect/Get) design pattern. After successfully processing a form POST request, the controller returns a redirect response (HTTP 302). Success notifications are transmitted across the redirect using Spring MVC's RedirectAttributes.addFlashAttribute(), which stores the notification in the user's session temporarily and purges it after rendering."*
3. How does form validation work from frontend to backend? *"We use JSR-380 annotations (such as @NotBlank, @Size, and @Email) on the DTO. The controller accepts the DTO marked with @Valid alongside a BindingResult object. If validation fails, the controller returns the original template name without redirecting, allowing Thymeleaf's #fields.hasErrors() to highlight invalid inputs with Bootstrap's is-invalid class."*
4. How is the UI secured based on the logged-in user's role? *"We integrate the Thymeleaf Spring Security Dialect using the sec:authorize attribute. Navigation links and administrative actions are rendered conditionally (e.g., sec:authorize='hasRole("ADMIN")'). Furthermore, even if an attacker manipulates the client HTML, Spring Security's SecurityFilterChain enforces strict authorization on the server."*
5. How do cascading dropdowns work without refreshing the page? *"We use standard JavaScript fetch() in location-dropdown.js. When the user selects a Province, an asynchronous GET request hits @RestController LocationController at /api/locations/provinces/{provinceId}/cities. The controller queries CityRepository, serializes the result to JSON, and the frontend dynamically constructs new <option> elements."*
6. How is CSRF handled across both forms and AJAX calls? *"Spring Security generates a unique cryptographic token stored in the user's HTTP session. For standard HTML forms, Thymeleaf injects the token into hidden _csrf input fields. For AJAX requests, the token is extracted from HTML meta tags and attached as an X-CSRF-TOKEN request header."*
